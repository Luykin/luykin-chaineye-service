01 / SUMMARY

先看重点

KOL Match 的 P0 架构已经搭起来，数据覆盖也从早期短板变成可用状态；现在最要优先处理的是取消、权限和过滤一致性。

当前 active KOL embedding 覆盖100%
AI 精准匹配单次最多返回20
条件筛选单次最多返回200
✓

方向正确：产品层与底层搜索层分离

前端统一走 /api/echohunt/kol-match/*，后端产品层处理登录、quota、SSE、安全 gate，再复用 kol-marketing/search-service.js 做 embedding 与只读 PG 检索。

!

三个最高优先级风险

一是 SSE 取消后后端仍可能继续执行并扣 quota；二是 AI 搜索底层可能二次自动推断过滤条件，导致用户关闭“排除低意愿”仍被过滤；三是前端 VIP 门槛与后端仅登录鉴权不一致。

02 / USER FLOW

前端用户可以做什么

当前产品分为 AI 精准匹配和条件筛选两条主路径，两者都依赖 EchoHunt Auth Center token，前端还额外做了 VIP 入口控制。

AI Precision Match

AI 精准匹配

用户输入项目 X 账号、项目与营销需求，设置少量硬条件；后端先生成策略，用户确认后通过 SSE 展示真实执行进度，并返回推荐名单。

Filter Search

条件筛选

用户按领域、市场、专业能力、灵魂指数、影响力范围、粉丝量、近期活跃度、接单意愿做筛选，最多展示 200 个结果。

项目账号验证

前端调用 GET /kol-match/project-account/lookup，后端调用内部 Twitter 用户查询服务，失败时可本地 fallback。

生成搜索策略

前端调用 POST /kol-match/strategy，后端先做安全 gate，再用 LLM 或规则 fallback 生成项目理解、目标 KOL、semantic query 和 filters。

确认并生成名单

前端调用 POST /kol-match/ai-search/stream，后端依次执行 quota 检查、账号验证、embedding、DB search、ranking，最后有结果才扣 AI quota。

打开 KOL 详情

结果列表点击后调用 GET /kol-match/kols/:twitterUserId，展示头像、浏览量、能力标签、接单证据、更新时间等字段。

05 / RISKS

缺陷与风险清单

这里按影响面和修复紧急程度排序。P0 建议上线前或下一轮优先修。

优先级问题影响建议
P0 SSE 取消后，后端仍可能继续执行并扣 quota 用户点击“修改需求”以为取消，但后端可能继续 LLM / embedding / DB / ranking，最终成功后仍扣 AI 次数。 给 runAiMatch 传入 isClosed()，关键阶段检查连接状态；关闭后不扣 quota、不写 final cache。
P0 AI 搜索底层二次推断 filters composite query 里包含营销/合作词，底层规则可能自动加 medium/high，导致关闭“排除低意愿”仍过滤 low。 给底层搜索增加 skipAutoFilterExtraction 或新增“纯 semantic query + 显式 filters”方法。
P0 前端 VIP 与后端权限不一致 前端只有 VIP 能进入，但后端 KOL Match API 只要求 Auth Center 登录。直接调接口可能绕过前端门槛。 明确产品策略：若仅 VIP 可用，后端补 VIP 校验；若登录即可用，前端不要隐藏入口。
P1 指定 KOL 查找没有真正调用后端 lookup 当前只是筛选已加载的 200 条，本来符合条件但未出现在当前列表中的 KOL 搜不到。 增加“查找”按钮；本地未命中后调用 /kols/lookup。
P1 近期活跃度过滤存在窗口漏召回 后端先取 scan window 再查活跃度，性能安全但不是全库严格排序后的完整命中。 前端不要把 candidateTotal 表达成全库总命中；中长期预计算 last_active_at。
P1 详情抽屉指标计算时间显示错字段 后端返回 metricsCalculatedAt，前端未映射，页面用 updatedAt 代替。 KolProfile 增加 metricsCalculatedAt 并在 Drawer 使用。
P1 仍有“原型阶段”文案 详情页推荐分说明有“原型阶段可复现演示分”，真实产品感不足。 改为真实推荐分解释。
P2 观测性不足 线上日志 morgan 中仍常见 anonymous/no-tw-id，不利于按 Auth Center 用户排查。 透传 request id；日志加入 authCenterUserId、clientKey、xhuntUserId。
06 / NEXT ACTIONS

建议优先级

按“影响用户信任 → 影响推荐准确性 → 影响运营排查”的顺序处理。

先修

取消 SSE 不应继续扣费

这是用户信任问题。修完后再压测断开连接、浏览器返回、切页面等场景。

先修

AI 产品层禁用底层二次自动硬过滤

strategy 已经负责理解需求，底层 search-service 不应再从 composite query 推断 willingness 等硬过滤。

决策

统一 KOL Match 的权限策略

如果是 VIP 功能，后端必须 enforce；如果是所有登录用户功能，前端应该展示入口并通过套餐 quota 控制。

近期

补齐详情字段和 lookup 体验

修 metricsCalculatedAt、去原型文案、真正接通指定 KOL lookup。

持续

补 739 条 AI 画像刷新

embedding 已完整，下一步质量瓶颈是画像 freshness 和标签/摘要质量。
